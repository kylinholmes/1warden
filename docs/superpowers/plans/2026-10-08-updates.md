# Desktop Updates Implementation Plan

> **For agentic workers:** Use subagent-driven-development or executing-plans to implement and verify the tasks below.

**Goal:** Automatically prepare verified desktop updates and prompt for an explicit restart.
**Architecture:** Official native updater verifies/installs; a desktop-only controller schedules checks and publishes UI state; tagged GitHub CI signs and publishes the matching update manifest.
**Tech Stack:** Tauri 2 updater, React/TypeScript, Vitest, Rust, GitHub Actions.
**Spec:** ../specs/2026-10-08-updates-design.md

## Global constraints

- Apple Silicon macOS only; retain `app.coffer.desktop` and local account compatibility.
- Public GitHub Releases endpoint; no GitHub credential is stored in the application.
- Never quit automatically. Download completion means installation succeeded and a normal next launch can use the update.
- Signing key never enters Git, logs or PR builds. Only trusted version tags create signed updater artifacts.
- Existing app memory, credentials and personal vault are untouched by tests.

## Review focus

- A failed or invalid update must never show a successful restart prompt.
- Repeated scheduled/manual checks must not download the same ready version twice.
- “稍后” must preserve the Settings restart action and current vault session.
- Extension/mobile/quick windows must not invoke native updater operations.
- Manifest version, signed version and ARM64 archive must agree; reject tampering.

### Task 1: Native updater and signing contract

Files: Cargo.toml/lock, package.json/lock, tauri.conf.json, updater capability, Rust update/restart command, docs/updates.md.

- [x] Pin official updater, initialize only on macOS desktop, configure public key and release endpoint.
- [x] Restrict updater and explicit restart to the main window; preserve identifier and existing native functions.
- [x] Verify an actual signed ARM archive, reject altered bytes/signature/version, and build native packages.

### Task 2: Controller, Settings and small ready notification

Files: desktop update controller/backend/component/tests, Settings.tsx and main.tsx.

- [x] Add injected-backend tests for no update, check/download errors, concurrent checks, progress and ready deduplication.
- [x] Implement a 10-second initial check and six-hour schedule; prepare using check/downloadAndInstall.
- [x] Add “稍后” / “重启更新” notification and Settings status/retry; test dismissal and explicit restart failures.
- [x] Verify platform exclusion, UI in headless preview, typecheck and shared frontend builds.

### Task 3: Signed release pipeline

Files: build.yml, updater-manifest helper/tests, version files and build/update documentation.

- [x] Test manifest ARM target/URL, missing signatures and invalid version rejection.
- [x] Branch/PR builds override updater artifacts off; trusted tags receive the signing secret.
- [x] Implement publishing signed tar.gz/.sig, latest.json and checksums alongside manual browser/macOS packages.
- [x] Run actual GitHub CI/release, download assets and verify metadata, archive architecture and signatures.

User authorized creation/push, public visibility and automatic updating. Root owns release/key setup; native and UI workers implement non-overlapping files, followed by an independent review. No additional approval is needed for these implementation steps.


## Verification evidence

- First packaging CI run `37667181798` passed every build/test job. Downloaded Chromium ZIP passed integrity; restored macOS `.app` was ARM64 and passed strict/deep codesign validation. Both local and GitHub build real App/DMG artifacts.
- Final updater frontend: `bun run check` passes **1,048 tests / 83 files** and TypeScript. The 13-check headless Edge report covers no-update, progress, install-complete boundary, postponement, explicit restart failure/retry and focus preservation.
- Native adapter separately bounds manifest and archive network operations (15 seconds / 5 minutes). Download timeout is not inherited from check; the regression was observed failing before the fix.
- Desktop/mobile/extension production builds pass; compiled mobile/extension JavaScript contains none of `plugin:updater`, `app_updates_supported`, `restart_app`. Desktop includes updater functionality, quick-window entry does not start it.
- Actionlint passes the final release workflow. New public releases remain drafts until all assets upload; manifest-last reruns reduce inconsistent update windows. Signed-artifact and actual tag-release evidence follows after native verification.

- Signed local native `0.1.0` App/DMG/updater archive built successfully. Root reran the exact pinned-plugin headless verifier: altered bytes rejected before install with original disposable app intact; manifest version inflation rejected; downgrade not offered; valid update replaced only the disposable app and left the running process on its old runtime while disk version became `0.1.0`. Native tests: **35 passed / 4 intentionally ignored**. Source and updater ACL review has no unresolved findings.
- Initial `0.1.0` installation is manual because `0.0.0` had no updater. Future signed releases are prepared automatically. Private signing key has mode `0600`, is outside the repository and was confirmed absent from repository files; GitHub contains only the configured Secret and source contains the public verification key.
