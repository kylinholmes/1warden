# PC 界面直接运行于浏览器扩展

用户目标：移除现有扩展独立 UI，以现有 PC 页面为唯一实现，优先完成 Chrome 与 Firefox 扩展，使多端操作近乎一致。允许保留必要的浏览器专属代码，并要求代码审查及针对不合理设计的重构。

## 方案

保留并改造 `src/App.tsx`、`src/screens`，由桌面入口和扩展入口直接渲染相同 App。导航、列表、排序、详情、编辑、设置、生成器、导入、安全报告和样式只有一套，删除旧 Popup/ItemDetail 与独立布局 CSS。尺寸由共同布局响应，扩展 CSS 只定义弹窗视口尺寸，不重新实现页面。窄屏必须能从详情返回、从报告/导入打开导航。

相比继续逐个抽共享小组件，这能从依赖关系消除整页分叉；相比在弹窗创建独立 VaultClient，这能保留关闭弹窗后自动填充和解锁会话。浏览器专属的当前站点、填充与保存提示，通过共享页面中的能力插槽展示。

## 数据边界

`application/types.ts` 定义页面依赖的 ApplicationClient。桌面在本地调用同一 ApplicationService；扩展通过明确列举的方法向后台调用该服务。后台继续独占会话与密钥，列表只传摘要；详情按需取单条展示数据，密码/隐藏字段/历史/私钥/卡号单独揭示。显式编辑单条记录时可获取可编辑字段，禁止传出会话密钥、Passkey 私钥、附件密钥和历史密码。保存只能更新编辑器拥有的字段，后台保留原记录的操作元数据，返回摘要。

所有 RPC 校验发送方及方法：页面内容脚本只能上报字段、提交或 WebAuthn 请求，不能调用 UI 读写接口。写操作完成后更新会话存储并通知 UI。锁定后清除旧详情与待处理结果，后台恢复不应重新打开已锁定的库。错误应保留认证、两步验证等结构供共享连接页面显示。

## 平台能力

Tauri 专属托盘、快速窗口、原生输入、证书确认仅在桌面入口或能力分支运行。浏览器实现文件下载、当前站点填充和持久于弹窗生命周期之外的剪贴板清理。Chrome 使用 service worker；Firefox 使用兼容的后台页面，统一 Promise API。两个构建产物从同一次源码构建生成，防止 Firefox 产物过期。

## 验收

- 扩展依赖图直接到 PC App/screens，旧独立 UI 删除。
- 相同数据和宽度下 PC 与扩展页面布局一致，窄屏导航与详情返回可用。
- Chrome 与 Firefox 实际浏览器：连接/锁定/解锁、搜索排序、详情揭示复制、编辑保存、文件夹、报告、导入、生成器、主题、填充与保存提示。
- 单测覆盖显示数据裁剪、保存元数据保护、消息权限、写后持久化、锁定与异步竞争；既有回归保持通过。
- 桌面、移动端及两个扩展构建通过，独立代码 review 的重大问题全部修复。

任务直接在当前工作区执行，保留原有未提交草稿的记录；草稿若被 PC 统一入口方案取代则作为此次重构删除，不把它误认成已接入的功能。
