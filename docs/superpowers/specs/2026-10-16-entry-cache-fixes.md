# 欢迎页延迟状态与头像缓存修复

## 延迟状态没有被手动测速覆盖

欢迎页自动探测写入按宿主传输和规范化服务器 URL 隔离的共享缓存，手动完整测速原先只更新 `ServerSpeed` 组件内的结果。下拉框和重新进入的页面继续读取五分钟缓存，因此会出现本次测速成功但仍显示“未连通”。

现在手动测速由同一共享服务管理：开始时发布“测量中”，成功或失败都会替换该服务器状态。登录、注册、下拉选项和测速行订阅同一结果。旧自动探测即使晚完成，也不能覆盖较新的手动结果。取消恢复之前已完成的结果；没有旧结果时回到待测量，不把取消当作连接失败。

回归用例覆盖欢迎探测失败后手动成功、跨登录/注册复用、再次失败与成功、旧请求乱序到达、取消及迟到结果。

## 登出清除了仍在欢迎页展示的头像和昵称

桌面服务和扩展后台原来都在登出时主动删除展示缓存，但欢迎页仍保留服务器与邮箱。因此反复登录再登出仍会丢失头像；这条路径与测速请求无关。

根据用户 2026-10-16 的明确要求，已记住账户的头像、昵称等展示信息持续保留。登出仍清除认证会话、密钥、令牌以及相关敏感状态。头像移除会保存新的展示资料；已完成且可信的服务器同步确认 Profile 被删除时，仍清理旧缓存。连接失败、同步未完成、锁定和切换不会把旧头像当作不存在。

缓存仍使用既有位置，没有迁移或重命名：

- 桌面：应用 WebView 的 `localStorage`；本机 Windows 宿主目录是 `%LOCALAPPDATA%\app.onewarden.desktop\EBWebView`。
- 浏览器扩展：该扩展的 `chrome.storage.local`。
- 逻辑键：`profile.v1.[服务器地址,规范化邮箱]`，值仅白名单保存 `displayName` 和 `avatarDataUrl`。同邮箱不同服务器互相隔离。

旧版已删除的本地缓存无法凭空恢复，需要成功解锁并完成一次资料同步；此后登出将保留它。
