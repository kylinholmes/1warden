# 1Warden 界面审计与设计优化方案 v1

日期：2026-10-28。审查基线：`0742a0a`。范围：现有 UI 的 audit 与 polish；本轮交付方案，未修改产品代码。

## 结论与设计方向

现有界面已形成清晰的工具型产品体系：蓝色操作与选中态、窄侧栏、密码库列表与详情、站点图标、上标签下内容的字段、固定操作栏。建议保留这套身份，集中修复信任与任务闭环，再处理密度和视觉细节。

**发布就绪的实现完整性判定：未通过。** 这不是视觉体系需要推倒重做：编辑器默认明文、泄露检查后评分不更新，以及重启绕过未保存内容保护，是应先处理的实际问题。检测器只报出一条 toast 左边框警告，并未发现这些关键缺口；低告警数不能代表产品已完成。

本轮收敛为 **20 组问题：P0 0、P1 5、P2 15、P3 0**。同类焦点问题按系统性原因归为一组；未证实的性能风险及主题约定不计入。

## 审查方法与边界

- 按用户要求分给 **3 个 GPT-6.1-Sol agents**：密码库/详情/编辑/安全报告；登录/解锁/快速访问/扩展；设置/资料/生成器/导入导出/组织/共享系统。主线程交叉核对源码与渲染证据。
- 使用 Impeccable `audit.md` 与 `polish.md`；context 选择 `apps/desktop`。未发现该目标的 PRODUCT.md 或 DESIGN.md，现有 CSS、组件和资产作为视觉权威。`docs/reference/design-system.md` 部分早期字体、配色说明已经落后于实际代码，不据旧文档更换现有主题。
- 启动项目现有假数据预览，用隔离的 **Edge 156** 检查；未登录真实保险库，未执行真实导入、永久删除、上传或安装重启。
- **23 个桌面预览状态**运行 axe-core 4.11：1280×900、390×844、320×568、620×400、360×400，包含浅/深色、列表、详情、新建、生成器、设置、导入、账户选择、安全报告和快速面板。
- 另构建并检查 **8 个移动/扩展预览状态**：各自编译平台的 vault/form/generator/settings，390×700。移动预览启用 Chromium mobile/touch 模拟，区别于桌面窄窗口。
- 额外交互：已有条目编辑；排序 Escape；快速解锁→密码→2FA→错误恢复；899→900px 设置切换；无空格长字段详情；移动编译版原生 range 合成触摸点击。共保存 **39 张截图**。
- 在上述 23 个自动扫描状态中没有捕获到页面运行异常，也没有页面级横向溢出。axe 仅报告 `region`、`landmark-one-main`、`page-has-heading-one` 等结构性最佳实践项，没有报告文本对比违规；这不覆盖非文本边界、键盘任务闭环、所有交互状态或所有调色板。
- 3 份预览构建成功。20 个现有相关测试文件 **232/232 通过**；主要保证数据、会话与流程规则，不能证明本报告的视觉和辅助技术问题不存在。
- 当前核查是源码与 Chromium 渲染，**不是 Windows WebView2/macOS WKWebView 真机核查**。Home、Register、凭据确认、组织合并、导入结果等未有完整夹具的状态以源码审阅为主；未声称完整视觉验证。未测试 NVDA/VoiceOver、Firefox 扩展失败回路、软键盘/原生安全区、所有触摸拖动或 200% 浏览器缩放。

证据位于 [审计产物目录](../artifacts/impeccable-audit-2026-10-28/)：`browser-results.json`、`interaction-results.json`、`detector.json`、截图及复核脚本。产物目录被现有 `.gitignore` 忽略；这份方案可独立纳入版本控制。

## 优先修复的 5 项

### A01 · P1 · 编辑已有条目时默认展示秘密

**位置：** `packages/ui/src/ItemEditor.tsx:256`、`:263`；对照 `EditorCustomFields.tsx:74`。

原生秘密字段的 `secret` 只改变字体，input 没有 `type=password`，SSH 私钥直接是 textarea。已有条目进入编辑即显示密码、相关 PIN 或私钥，缺少明确揭示步骤。与既有“永不默认明文展示”原则不符。

**证据：源码 + Edge。** 登录编辑夹具实测 `type=text`、有值、`-webkit-text-security=none`，见 [编辑秘密字段截图](../artifacts/impeccable-audit-2026-10-28/form-edit-visible-secret.png)。截图只有仓库自带虚构凭据。

**方案：** 统一编辑秘密字段，默认遮蔽；保留独立的“显示密码/隐藏密码”操作；私钥使用适合多行秘密的显式揭示流程；生成或复制不自动揭示。先处理登录密码、验证码密钥、卡片安全码、PIN、SSH 私钥，再检查其他秘密类型。命令：`$impeccable harden`。

### A02 · P1 · 泄露检查结果和安全评分不是同一版本

**位置：** `apps/desktop/src/screens/SecurityReport.tsx:46`；`packages/vault/src/health.ts:222`、`:334`。

检查成功只合并 `breached`，没有重算 score/grade；而现有算法明确把泄露数作为最高权重扣分。可能同时显示“已泄露”与之前的高分。

**证据：源码确定；未向 HIBP 发起真实查询。** 例如 10 条其他项正常的记录发现 1 条泄露，现有算法应从 100 变为 70，当前 UI 合并路径仍保留旧分。

**方案：** 服务层一次返回同版本完整报告，让总分、评级、摘要和明细一起更新。保留用户主动开启第三方查询的约定。命令：`$impeccable harden`。

### A03 · P1 · 更新重启绕过草稿与自动保存保护

**位置：** `AppUpdateNotice.tsx:20`、`:31`；`AppUpdates.tsx:27`；`updates/controller.ts:125`；对照 `App.tsx:134`。

两个重启入口直接调用 updater，未经过自动保存 flush 或条目编辑离开确认。更新提示 z80 高于模态层 z50，鼠标路径也可能在编辑中触发重启。

**证据：源码调用链确定；没有实际重启，也没有制造数据丢失。** 用户尚未保存或资料保存失败时，有丢失当前内存修改的风险。

**方案：** 统一安全离开协调器；先完成资料保存，失败时留在原处重试；对条目草稿显示保存/放弃/取消；保护通过后才执行现有更新动作。命令：`$impeccable harden`。

### A04 · P1 · 快速搜索的当前选择没有传达给辅助技术

**位置：** `QuickAccess.tsx:83`、`:116`、`:150`、`:166`。

方向键只改变列表按钮的背景和 `aria-current`，焦点仍留在搜索框；输入框没有 active-descendant 关系或等效播报。屏幕阅读器无法可靠获知 Enter 将复制哪一项。

**证据：源码及现有焦点保持测试；未用 NVDA 实听。** 涉及当前控件状态及关系的可访问性。

**方案：** 搜索采用完整 combobox/listbox 交互，稳定 option ID、当前项、结果数和无结果播报；把嵌套复制等动作放在符合该模式的位置，不能只机械添加 role。保留当前搜索框和选中视觉。命令：`$impeccable harden`。

### A05 · P1 · 空白输入框的必要边界对比不足

**位置：** `packages/ui/src/components.css:607`；`packages/ui/src/theme.css:102`、`:186`。

浅色 `.field` 使用 `#94abc9` 边界和白色背景，WCAG sRGB 对比约 **2.35:1**；小于必要控件边界要求的 3:1。暗色同一 token 在 overlay 上约 2.89:1，应逐场景复核。

**证据：源码 + 渲染计算样式。** 已在实际编辑输入确认 border=`rgb(148,171,201)`、background=白色；对应非文本对比 WCAG 1.4.11，不是 axe 已报告的文字对比失败。

**方案：** 新增或明确“必要控件边界”语义，与装饰分隔线分开；单独提高输入、选择、必要轮廓的对比，避免加深所有卡片和分隔线。检查正常/焦点/错误/禁用及全部支持调色板。命令：`$impeccable colorize`。

## 分模块设计优化方案

### 1. 密码库、导航、搜索与列表

**保持：** 当前三栏骨架、900px 切换、窄窗单页、分类色、站点图标、整行选中。

**调整：** 整理搜索/排序/新建工具栏的命名与焦点契约；排序继续使用紧凑下拉，不改成挤占搜索宽度的分段控件。详情与列表明确当前关联。空库提供就地新建；无搜索结果提供清空搜索；收藏空态引导收藏已有条目。宽窗新建文字是否容纳以336px列表栏实测决定，不强行加字挤压搜索。

**验收：** 鼠标与纯键盘都能搜索→改排序→选记录→开详情→返回；Esc 只关闭当前最内层；返回保留搜索与滚动。长名称可辨认，当前记录和收藏有辅助技术语义。

### 2. 详情与编辑器：提高首屏效率

**主要视觉问题：** 390px 新建页把8类条目展开成4行卡片，约占290px，名称到约470px才出现；在390×700移动预览里，主要凭据几乎都在首屏以下。每个字段再叠一层描边，阅读层级容易被轮廓分散。

**调整：** 窄窗把类型区收为当前类型的一行选择器，点击展开所有类型；桌面可保留现有类型网格。名称和当前类型核心字段上移；高级设置、额外字段仍按现有语义逐步展开。分组以标题+留白为主，必要输入边界保持清晰，避免“外卡片+内卡片+每行分隔”同时争夺注意。保留字段标签在上、内容在下及固定保存栏。

建议首屏顺序：**页面标题 → 当前类型选择 → 名称（必填） → 用户名 → 已遮蔽密码/显式揭示 → 网址 → 扩展信息**。这是现有字段的布局调整，不改数据模型。

**验收：** 390×700无需先滚过类型墙即可看到名称、用户名、密码；320px无逐字窄列；多行私钥和OTP密钥不默认露出；保存失败可回到错误字段；切换900px断点不丢草稿。

### 3. 安全报告：从“看见问题”到“完成修复”

**调整：** 总分、风险摘要、明细同一版本更新；优先展示当前可处理的问题及清晰操作。第三方泄露检查仍保持主动开启，先给简短解释，再展开技术细节，避免长说明挤走已知弱密码。技术事实不改写成新的安全承诺。

```mermaid
flowchart LR
  A[风险摘要] --> B[问题条目]
  B --> C[条目详情]
  C --> D[编辑与保存]
  D --> E[返回报告并更新结果]
  E --> A
```

重复密码组可展开到具体记录；每一项显示问题原因及“查看条目”。返回后保留上下文。评分继续作为解释性摘要，不新增装饰仪表盘。

**验收：** 不需手动记住名称再搜索；返回时不用重新找问题；泄露结果改变时评分、评级、数量一起改变。

### 4. 入口、账户与快速面板

**保持：** 简洁入口、现有账号卡、快速面板尺寸、就地密码/2FA流程、切换与取消机制。

**调整：** 同邮箱账户增加常驻服务器标识；搜索结果选择采用完整可访问模式；结果数/无结果/复制失败有简短反馈。复用主界面的账户身份规则，避免 Home 显示服务器、quick 又隐藏服务器。低高度返回按钮本轮未确认重叠，不据猜测改布局。

**验收：** 360×400完成账户→密码→2FA→错误重试→搜索；同邮箱不同服务器不依赖悬停区分；屏幕阅读器可确认当前选项及复制目标；失焦仍清空已输入秘密。

### 5. 设置、资料、生成器与更新

**保持：** 设置窄窗目录逐级进入、宽窗侧栏、外观缩略图、资料自动保存的完整状态。

**调整：** 生成器窄宽采用上下结构，选项两列；强度结论先短句，解释与参数分层，避免小字长段落占用核心控制区。输入边界与装饰线分离。更新提示保持克制，但重启必须经过统一安全离开。不要为了让 polish 显眼而新增动画。

### 6. 导入、导出、组织与回收站

**保持：** 导入先预览、默认跳过已有记录；导出默认加密及明文警示；组织合并先保存再回收、冲突处理；永久删除范围确认。

**调整：** 明确“选择来源→预览范围→确认执行→结果/恢复”的阶段层级；把格式说明和长兼容列表收进按需展开的说明区域，保留关键风险及文件上限常驻。成功/部分失败统一摘要、后续动作和焦点；危险操作与正常数据搬运在页面上拉开距离。

**验收：** 用户可明确回答“当前账户、将处理几条、哪些跳过、哪些失败、怎么继续”；取消、恢复、重试后都有稳定操作位置。大规模异常详情先测量，再决定分页/分批渲染。

### 7. 扩展保存提示与网页内选择器

**调整：** 待保存确认卡接回共享 token 与 field；到达、完成和失败用简短状态反馈；处理后焦点移动到下一张卡或原任务。网页内浮层继续用 shadow DOM 隔离，不继承宿主页CSS。

**验收：** 键盘填充失败可原地重试，保存下一张确认卡不需从页面开头Tab；Chromium与Firefox分别覆盖失败状态。网页内是否遵循扩展显式主题属于产品约定，先明确再统一。

## 复核结果、优点与未决项

**值得保留：** Select 已实现方向键、Home/End、typeahead、Escape、popover top layer、visualViewport定位及forced-colors；账户菜单、资料自动保存、组织合并已有成熟状态契约，应向其他模块复用。列表/详情在断点切换时保留上下文，长无空格字段的390px详情未出现容器溢出。快速2FA错误后焦点回到验证码输入，360×400布局未观察到返回控件重叠。移动编译版range用合成触摸点击成功从20变为55；这只证明该手势在当前Edge模拟环境有效。

**检测器误报处理：** `styles.css:452` 的3px toast左边框是现有success/warning/danger语义反馈的一部分，配合图标和文本使用。本轮保留，不因“side-tab”装饰模式告警机械删除；告警见 `detector.json`。

**不计作已证实缺陷：** 大库filtered.map缺少虚拟化、ImportView异常明细无上限创建DOM，均是可定位的规模风险，尚无真实延迟证据；未直接报告“已经卡顿”。配色弹层临近边缘裁切需交互夹具确认。原生checkbox尺寸小但有包裹label及规范例外，不能只看13×13就判触控不合规。外观自动同步已有SyncedPreferences实现，不报文案虚假。网页内UI只跟系统主题与扩展显式主题分离，需明确是否刻意。

**性能范围说明：** 3份preview构建均有大chunk提示，mobile预览主JS约1.10MB（gzip约396KB）。预览包含测试夹具与多页面集合，不能据此推断产品实际首包或冷启动慢。下一轮性能验证应测产品构建与1k/5k条库的输入延迟、长任务、滚动和导入异常摘要；再决定拆包或虚拟化。

**后续验证清单：** 原生壳最小尺寸/Windows 125%与150%/浏览器200%缩放、NVDA或VoiceOver、Firefox扩展、全部调色板、离线/慢速/同步错误、长字段、软键盘及安全区。修复后重跑 `$impeccable audit`；先把任务与状态修完整，再用 polish 统一细节。
