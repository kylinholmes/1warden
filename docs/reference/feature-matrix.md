# 1Password 功能 × Vaultwarden 能力 × Coffer 现状

> 这份矩阵回答三个不同的问题，**不要把它们混为一谈**：
>
> 1. **1Password 有没有** —— 我们复刻的目标
> 2. **Vaultwarden 支持不支持** —— 协议层给不给路。这一列决定的是「要不要
>    自己做」，不是「能不能做」
> 3. **Coffer 做到哪了** —— 代码里的实际状态
>
> 第 2 列是 ❌ 的那些，几乎全都是**客户端自行实现**（服务端没有对应的
> `/api/reports/*` 之类）—— 那反而是好事：数据不必离开设备。
>
> 状态图例：✅ 已实现且验证过 · 🔶 已实现但**未实测** · ⬜ 未开始 · ❌ 不可能

## 7. 做不到的事（诚实清单，不要等用户踩坑）

| 能力 | 为什么 | 差异对用户意味着什么 |
|---|---|---|
| **Secret Key** | Bitwarden 的模型是「主密码单独决定一切」。保持互操作就无法加第二因子到密钥派生里 | 真实的安全强度差距。**文案上不能暗示我们有** |
| **系统级 passkey（桌面）** | 需要独立的 Swift/ObjC Credential Provider 扩展 target + 特殊签名，Tauri 给不了 | 桌面端不能用 passkey 登录别的应用 |
| **Windows UAC / 提升权限的应用** | 完整性级别差异，**没有用户可授予的权限能解决** | 那些窗口里填不了 |
| **wlroots / Hyprland 下的 Wayland 按键合成** | 根本没有 RemoteDesktop portal | Linux 天花板，且要如实告知 |
| **游戏 / 自绘 UI** | 没有可访问性树 | |
| **Mac App Store 上架** | 第三方沙箱应用拿不到按进程的 `com.apple.axserver` | 走 Developer ID + 公证 |

## 8. 与官方客户端的兼容性缺口

`@bitwarden/cli` **2026.x** 登录后会执行「用户密钥 ID 回填」，调用 Vaultwarden
未实现的端点而失败（`KeyIdBackfillError`，404）。登录**本身**成功，失败在登录之后。

这不是我们的 bug，是**上游的兼容性缺口** —— 真实用户用新版 CLI 或新版官方客户端
对接自建 Vaultwarden 时会撞到，值得写进产品文档的「已知问题」。
我们的客户端**不调用这个端点**。
