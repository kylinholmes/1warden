# 1Warden 登录与快捷解锁结构预览

> 已选定：登录 A、快捷解锁 B。正式快捷解锁仅用于桌面，未采用本目录的窄屏折叠交互。这些原型保留为历史备选；已接受的实现决策与验证边界见 [登录与桌面快捷解锁](../../../../docs/login-and-quick-unlock.md)。

以下记录最初供选择的独立 HTML/CSS/JS 原型，采用现有品牌图标、系统字体与蓝色主题。制作原型阶段没有改动正式应用与认证代码。

在仓库中运行：

```powershell
cd apps/desktop
bun run vite --config vite.preview.config.ts --host 127.0.0.1 --port 4389
```

打开 <http://127.0.0.1:4389/entry-concepts/>。可切换三种结构、登录/快捷解锁、浅色/深色；桌面与窄屏同时预览。原型演示密码为 `preview`，其他非空密码演示错误反馈。账户均为虚构数据，不发送网络请求、不保存凭据、不使用系统剪贴板。

| 方案 | 登录 | 快捷解锁 | 取舍 |
| --- | --- | --- | --- |
| A 聚焦表单 | 单页表单；服务器身份可见、设置按需展开 | 紧凑账户行、明确标题、主密码与主操作 | 高频操作直接；切换账户多一次展开 |
| B 明确分区 | 服务器与账户分两步；预览从账户步骤开始，可返回选择服务器 | ≥480px 账户/密码分栏；窄窗口折叠账户选择 | 信息分区清楚；完整首次登录流程增加一步 |
| C 账户优先 | 已保存账户与解锁为主，保留其他账户登录 | 账户列表内展开主密码 | 多账户辨认方便；无账户时需退回完整登录表单 |

## 范围与事实来源

- 根据用户后续说明，快捷小窗口优化重点为选择账户和密码解锁；搜索结果界面不在本轮方案范围。
- 产品事实来自 README.md、ConnectScreen.tsx、Home.tsx、QuickUnlockPanel.tsx、QuickLockedAccounts.tsx。
- 登录预览为 960×720 和 390×760；快捷解锁为 620×400 和 360×400。窄布局不使用头像横向轮播。
- 与正式程序相同，主密码用于本地派生密钥的说明保留；未添加生物识别或其他未实现的登录能力。
- 图标直接使用既有 packages/ui/src/brand/app.png 的副本，SHA-256 一致。源图标未修改。原型在 24/32px 也展示这份 app 图；正式 BrandMark.tsx 在 ≤32px 使用 compact.png，接入时应复用该组件。
- concept.css 选取 packages/ui/src/theme.css 的浅色/深色调色板，以局部别名重组表面层级，系统字体栈为精简副本。字号与控件圆角含本轮原型值（如 28px 标题、8px 控件圆角），尚未确认为全局规范。本轮以完成任务和减少噪声为准。

## 原型与接入边界

当前原型用于结构比较，支持字段输入、显示密码、账户选择、返回步骤、错误与等待反馈。真实的注册、两步验证、证书确认、取消与请求过期处理仍由正式应用负责；选定方案后再接回这些既有行为。快捷窗口里的固定、关闭和解锁结果仅做原型状态演示。B 的服务器选择在步骤切换时保留；正式接入时复用既有公开字段草稿。

原型源文件全部在本目录，启动复用 apps/desktop/vite.preview.config.ts。截图和浏览器检查记录位于仓库 artifacts/entry-concepts/（被 gitignore 排除）：

- layout-checks.json：三种方案、两种主题，共 48 组宽度/页面检查；记录中均无横向溢出、主操作均可见。登录宽度覆盖 320/390/768/960/1440px，快捷解锁覆盖 360/620/775px。
- browser-checks.json：6 组交互检查，覆盖三种快捷解锁的账户选择、密码焦点、显示密码、错误和 Enter 解锁，B 的服务器步骤，以及 390/1440px 画廊切换；错误列表为空。
- compare-*.png 为三方案对比，gallery-*.png 为预览入口截图。以上只验证浏览器原型；不代表已验证真实认证或原生窗口行为。

没有选定新视觉系统，因此不改写全项目 DESIGN.md 或 PRODUCT.md，也不生成 .impeccable 文件。
